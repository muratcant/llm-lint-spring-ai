Reports Spring AI ChatClient calls (.call() / .stream()) that have no output token limit.

Without a limit the model decides how long the answer is. Spring AI 2.x no longer applies a small default, so answers can get several times longer, and so does the bill.

The inspection stays silent when a limit is set in any of these places:

  • the request: .options(ChatOptions.builder().maxTokens(512)) (also maxCompletionTokens, maxOutputTokens, numPredict);
  • the client: ChatClient.builder(model).defaultOptions(...), or the options of a ChatModel built in code;
  • configuration: spring.ai.<provider>.chat.options.max-tokens in application*.yml / application*.properties.

When the options come from somewhere it cannot see (a method parameter, a bean defined in a library), the inspection assumes they are set, to avoid false alarms.

Example:


// Reported
chatClient.prompt().user(question).call().content();

// Fine
chatClient.prompt().user(question)
    .options(ChatOptions.builder().maxTokens(512))
    .call().content();
